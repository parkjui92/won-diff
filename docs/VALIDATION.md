## 브라우저에서 확인하는 내용

1. 공개 예제 불러오기 → 비교 → 표기 변경 필터 → 원문 근거 → JSON 다운로드.
   내려받은 JSON의 차액 `2869000000`원과 SHA-256 형식을 확인.
2. 기준을 바꾸면 기존 결과가 무효화되며, 예산/결산 비교 시 증감률을 억제.
3. CSV를 실제 파일 선택에 넣고 중복 키가 비교를 차단하는지 확인.
4. 실제 XLSX 수식 셀을 확정값으로 사용하지 않고, 손상된 XLSX를 거부.
5. HTML처럼 생긴 식별자를 실행하지 않고 문자로 표시. 모바일 폭에서 가로
   넘침 여부, Enter로 근거 열기, Escape로 닫기 확인.
6. 브라우저 네트워크를 차단한 채 `file://`의 단일 HTML을 열고, 생성한 XLSX
   두 개를 실제 업로드해 비교. HTTP 요청 0건 확인.

1번 시나리오에서는 POST 등 쓰기 요청과 JavaScript 오류가 없는지도 검사한다.
입력 내용은 서버에 보내지 않는다. 이 검증은 전면적인 보안 감사나 모든 브라우저
호환성 인증을 뜻하지 않는다.

## 금액 계산과 오류 처리

- 숫자를 JavaScript 부동소수점으로 먼저 변환하지 않고 문자열에서 Decimal로 파싱.
- 2^53을 넘는 정수 문자열도 정확히 비교. XLSX 숫자 셀이 안전한 정수 범위를
  넘으면 원천값을 확인하도록 판정 보류.
- 원/천원/만원/백만원/억원/조원, 소수, 쉼표, 음수, 복합 단위를 검증.
- `▲`의 의미, 주석, 잘못된 쉼표, 외화, 과학적 표기 등을 추측하지 않음.
- 결측과 0, 수식과 확정값, 표기 변경과 실질 금액 변경을 구분.
- 키 중복·헤더 중복·추가/삭제·합계 혼입·지정 소계 불일치·기준 불일치를 검증.
- CSV 내보내기에서 사용자 문자열이 수식으로 해석되지 않도록 처리.
- CLI 종료 코드 0/1/2/3과 기존 파일 덮어쓰기 거부를 실제 프로세스로 검사.

## 실행 환경과 한계

로컬 검증: macOS, Node.js 22.22.0, Chrome, Python 가상환경.
CI: GitHub Actions Ubuntu, Node.js 22, Python 3.11, Playwright Chromium.
정확한 라이브러리 버전은 `package-lock.json`과 `benchmarks/requirements.txt`에 있다.

실제 기관 내부 자료, 임의의 다단계 계층표, 구형 XLS, 모든 Excel 수식과 표시형식,
사용자가 잘못 고른 단위·회계 기준을 검증한 것은 아니다. 10,000행은 입력 상한이며
모든 기기에서 특정 처리시간을 보장하는 성능 수치가 아니다. 압축 파일 상한은
ZIP 디렉터리에 선언된 크기를 확인하는 방어이며 악성 파일 분석기를 대체하지 않는다.

공개자료 검증은 수치가 있는 정부지원수입 세 항목과 소계에 한정한다.
범용 diff와의 비교는 개발자가 설계한 원화 표현 24쌍의 기능 실험이다.
독립 전처리를 한 범용 도구는 같은 판정 결과를 냈으며,
현업 사용 시간·오류율 개선이나 보편적 정확도 우위는 아직 측정하지 않았다.
