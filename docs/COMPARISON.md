# 기존 GitHub 도구와 비교

조사·실행일: 2026-10-21. 비교 목적은 한국어 예산표의 실질 금액 변경을 검토할 때 별도 준비가 얼마나 필요한지 확인하는 것이다.

## 후보 검토와 선택

| 도구 | 원문에서 확인한 강점 | 이번 업무에서 필요한 추가 작업 |
|---|---|---|
| [paulfitz/daff](https://github.com/paulfitz/daff) | 행·열 정렬, 3-way 비교, 패치·병합, CSV·SQLite·JSON, HTML 출력 | 한국어 원화 표현을 동일 단위로 변환하고 회계 기준·합계를 별도 관리 |
| [simonw/csv-diff](https://github.com/simonw/csv-diff) | 식별자 기반 CSV/TSV/JSON 차이, 단순한 CLI와 JSON 결과 | 금액 정규화, 금액 차액·증감률·원문 근거 기록 |
| [Quantco/tabulardelta](https://github.com/Quantco/tabulardelta) | Pandas/SQL 비교, 스키마·타입·행 차이, 수치 허용오차, 출력기 분리 | 원화 단위 표현의 전처리와 예산/결산 업무 규칙 |
| [datafold/data-diff](https://github.com/datafold/data-diff) | 대규모 DB 테이블 비교, 해시 기반 분할 비교 | 작은 업로드 파일과 비개발자 화면에는 목적이 다름. 이번 실행 비교에서 제외 |

daff의 조사 당시 HEAD는 `ad5a02efd58ea7a2a70bb888f65ab610d136db28`,
csv-diff는 `26903b74eefcd65be761810f51b0e55c033bde66`이었다. 실행에는 배포 버전
daff 1.4.2, csv-diff 1.2, TabularDelta 1.1.1을 사용했다. 최신 HEAD와 배포 버전을
동일한 것으로 부르지 않는다. 실행 버전과 모든 개별 결과는 `benchmarks/results.json`에 있다.

이 세 도구는 모두 유용하며 로컬 실행도 지원한다. “로컬 처리 자체”를 새 도구만의
장점으로 주장하지 않는다. won-diff는 병합·패치·SQL 처리·스키마 추론의 대체품이 아니다.

## 왜 기존 도구를 감싸는 대신 작은 계산 모듈을 만들었나

won-diff는 식별자가 사용자가 지정한 열에서 정확히 일치하는 평면 표만 다룬다.
자동 정렬이나 스키마 추론이 핵심이 아니므로 키 대응에는 Map을 사용하고,
금액에는 검증된 decimal.js, CSV에는 Papa Parse, XLSX에는 ExcelJS를 재사용했다.
독자 구현은 원화 표기 규칙, 비교 기준, 검토 상태와 화면 흐름으로 제한했다.

처음부터 LLM으로 원인 분석이나 사업명 유사도 매칭까지 넣으면 검증 범위가 커진다.
확인되지 않은 대응 관계를 만들지 않고 “추가/삭제”로 남기는 선택을 했다.

## 실행 비교 설계

- 과제: 주어진 두 표현의 **실제 금액 변경 여부**를 이진 판정.
- 데이터: 직접 작성한 24쌍. 실제 변경 12, 동일 금액 12. 동일 금액 중 표현 변경 10.
- 정답: 개발자가 `beforeWon`·`afterWon`을 별도로 적었다. 비교 실행 결과에서 정답을 생성하지 않았다.
- 원본 조건: 두 도구 모두 같은 문자열과 같은 `id`·`amount` 열을 받음.
- daff: `id`를 primary key로 지정, 행 순서 무시.
- csv-diff: `key=id`.
- TabularDelta: 문자열 데이터프레임, `join_columns=["id"]`, 행 순서 무시.
- 금액이 같은 표기 차이를 범용 도구가 변경으로 표시하면, **이 업무의 이진 판정 기준에서만** 불필요한 알림으로 센다.
- 정규화 대조군: 별도로 적은 원 단위 값을 세 범용 도구에 그대로 전달.
- 추가·삭제·중복 키·수식·회계 기준·합계 검산은 별도 기능 테스트이며 경쟁 도구의 점수에 섞지 않음.

| 원본 조건 | 실제 변경 탐지 | 실제 변경 누락 | 동일 금액 변경 알림 | 올바른 판정 |
|---|---:|---:|---:|---:|
| won-diff | 12 | 0 | 0 | 24/24 |
| daff | 12 | 0 | 10 | 14/24 |
| csv-diff | 12 | 0 | 10 | 14/24 |
| TabularDelta | 12 | 0 | 10 | 14/24 |

**독립 원 단위 정규화 후에는 세 범용 도구 모두 24/24**였다. 따라서 이점은
환산 전처리와 셀 근거·기준 경고를 바로 사용할 수 있다는 데 있다.
문자열 차이 자체를 정확히 보고한 기존 도구의 동작을 버그라고 부르지 않는다.

## 편향과 한계

이 데이터는 개발자가 지원하려는 원화 표기에서 구성한 기능 검증용 사례다.
독립적인 대규모 현업 평가나 무작위 표본이 아니다. “정확도 100%”를 일반 성능으로
광고하지 않는다. 규칙 밖의 표현은 판정하지 않으며, 사용자가 잘못 고른 단위·식별자·
시점·회계 기준까지 도구가 알아서 바로잡을 수는 없다.

원화 환산 모듈을 앞단에 붙인 기존 도구, 사용자 맞춤 Excel/Power Query 처리와의
사용 시간·실수율 비교는 수행하지 않았다. 범용 기능·성능·대용량 처리에서는 기존
도구가 더 적합할 수 있다.

## 재현

README의 설치 후:

```bash
python3 -m venv .venv
.venv/bin/pip install -r benchmarks/requirements.txt
npm run bench
```

다른 Python을 쓰려면 `BENCH_PYTHON=/path/to/python npm run bench`.
결과는 `benchmarks/results.json`에 저장된다. 네트워크는 의존성 설치에만 필요하다.
